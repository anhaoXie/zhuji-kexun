# 01 · 项目概述

> 《株迹可循》——面向「一株一档」的温室巡检与病害追溯智能机器小车
> 项目负责人：[@anhaoXie](https://github.com/anhaoXie)

## 1. 一句话

给小型温室的每一株苗建一份固定档案，用五级株位码认住同一株；巡检时对一株拍多角度照片，判断病害与「这次比上次重了还是轻了」，再给一份能照着做的农事管理建议。**让每一次巡检，都能回到同一株。**

## 2. 背景：三个麻烦，卡在同一处

### 2.1 看不准

常规巡检把相机吊在顶上，一个台位只拍一张俯视图。心叶被外叶包着，下部叶和叶柄基部贴着基质，叶背朝下——这几处病斑都容易被挡住。换棚、隔几天，光照、背景和株型一变，准确率继续下降。

数据泄漏会进一步放大这种虚高。Ouyang 等（2022）在温室番茄上的对照：

| 数据划分方式 | mAP@0.5 | Recall |
|---|---|---|
| 随机划分（同棚同日照同时进训练与测试） | 90.4% | 85.2% |
| **按拍摄日期划分（换天巡检的真实条件）** | **< 80%** | **≈ 69.8%** |

10 个点以上的落差说明：**换天巡检确实会掉这么多**，随机划分的高分靠不住。

### 2.2 说不清

即使这一株拍到了、也判出了病害，它处在什么阶段仍说不清。巡检结果通常只有「有病害/没有病害」，顶多再给一个病害框；对于同一株所处阶段——新发、持续、加重、好转、已处理或疑似误报——业内尚缺统一判定口径。三天后回看，多依赖照片与主观印象，不同人员复核的结论一致性较差。

### 2.3 用不上

工作人员看到「疑似病害」后，仍需自行判断是否隔离、通风、降湿、清除病叶或加密复查；检测结果与田间处置决策之间缺少衔接，报告难以为实际操作提供直接依据。

### 2.4 共同短板

三个问题看着分散，其实卡在同一处：**记录里没有「株」这个主键。**
回不到同一株，前后两张照片就不是同一株的两个时刻，新发还是加重没法判；状态判不出，建议只能凭印象给；准确率也只能报数据集平均分，漏了谁、误报了谁查不出来。

## 3. 方案：先建码，再巡检

```
建码 → 巡检 → 检测 → 补拍 → 六状态 → 建议 → 人工确认 → 报表
```

1. **建码**：每株一个五级株位码 `棚—行—台—位—株`；台位 4 株按固定方位（西南/东南/西北/东北）编号，苗床两侧贴同号 AprilTag 码牌。
2. **巡检**：麦轮底盘沿 S 形航线逐台位停靠；每个台位在两侧过道各停一次，每次拍近侧 2 株、每株俯视 + 斜视各 1 帧，**一个台位 8 帧**。
3. **检测**：K230 在车端完成码牌解码与病害检测，结果经串口回主控；低置信度（0.4—0.8）回同一停靠位补拍 2—3 张。
4. **六状态**：按「先误报、再处置、后病程」固定顺序判定，机器给初判与依据照片，人工确认、改判留痕。
5. **建议**：按「状态 × 严重度 × 生育期」查规则表，输出六类农事动作建议。
6. **复查**：按任务卡 60 s 内回到原株，前后照片并排核对；结果写回档案。

## 4. 设计原则

| 原则 | 落地方式 |
|---|---|
| **记录优先** | 株位码是主键，检测、状态、建议、操作人都挂在这个编号下，可逐株回溯 |
| **可复现** | 停靠位固定、云台角度固定、阈值版本化；同一批数据换个时间再跑，结论对得上 |
| **窄口径** | 单一作物、少量明显病害、已显症植株；先在地基上站住，再扩作物 |
| **人机协同** | 机器负责「回到同一株、给证据、给候选」，人负责最终确认；不承诺全自动无人值守 |
| **低成本可换棚** | 不改造温室结构，码牌带走重贴即可复用；已列价新增器件约 1,149 元 |

## 6. 创新点（系统层，不是新检测算法）

| 层级 | 内容 | 为什么算创新 |
|---|---|---|
| **核心创新** | 一株一档：固定株位码做主键，检测、六状态、建议都记在同一株下 | 现有工作（Ouyang 2022、AgriScout 2025、PhytoPatholoBot 2026）位置只到「管段+图像序号」/RTK 点/病害图，**公开摘要均未报告跨次找回同一株** |
| **支撑一** | 不依赖 RTK 的三层定位（台位/连续/株位） | 把「准确停回同一个点」从轨道搬到轮式，成本压到千元级，并让准确率可以按株统计 |
| **支撑二** | 拿不准就回同一株补拍 + 六状态固定判序 | 解决「判不出来怎么办」与「已处理/疑似误报混在一起没法统计」 |

## 7. 成果形态

- **实物整机 1 台**：视觉、主控、通信、电源、底盘齐套，可现场演示行走、逐台位停靠拍照、图传叠加检测框。
- **软件**：PC 棚务台、手机端（H5 + 微信小程序骨架）、本地服务、K230 设备端脚本。
- **算法与数据工程**：YOLO11n 轻量化检测、按原图分组的数据重划分、K230 ONNX→kmodel 部署链路。
- **文档**：设计、评测、边界、复现与参考文献（本仓库）。

## 8. 适用范围

**适用**：台架式/垄作小型温室；矮脚上海青；1—2 种外观明显病害；棚内平整通道、可贴码牌、可就近充电。

**不适用**：露地/坡地、全病害、早期无症状、自动施药、替代植保员。
